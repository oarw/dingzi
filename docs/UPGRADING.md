# 升级与运维

本文对应 `feat/complete-monitoring`。这次升级包含单机身份认证、历史字段、服务监控和告警表的变更。

## 版本配套

| 面板 | Agent / 安装脚本 |
| --- | --- |
| `v0.1.1` 及更早 | 使用对应旧版本的 Agent 和该标签下的 `install.sh` |
| `feat/complete-monitoring` | 面板和 Agent 从同一提交构建，或使用同一轮发布的配套产物和安装脚本 |

旧版 Agent 只使用共享密钥，本分支要求 UUID 和单机 token，不能混用。当前安装脚本还会调用
Agent 的 `--configure`，`v0.1.1` 及更早没有此参数；遇到该错误应使用对应版本标签下的脚本，
不要绕过配置检查。

安装脚本不指定 `--version` 时下载最新正式版。测试本分支的预发布时必须指定配套标签，例如：

```sh
# 替换成与面板配套的真实发布标签。
VERSION='vX.Y.Z-prNN'
curl -fsSL "https://raw.githubusercontent.com/oarw/dingzi/$VERSION/install.sh" | sh -s -- \
    --version "$VERSION" --server https://panel.example.com --secret '<注册密钥>'
```

PR 标签会随每次推送滚动更新，因此仅标签相同不足以证明来自同一提交。保存下载时的校验和与
发布对应提交，面板和 Agent 使用同一轮产物。尚未发布的分支可以在同一源码目录构建：

```sh
go build -o dingzi-server ./cmd/server
go build -o dingzi-agent ./cmd/agent
```

## 从旧版本升级

1. 记录当前版本和启动参数。停止面板及待升级的 Agent，备份面板完整 `--data` 目录、各台
   Agent 的配置文件和旧二进制。SQLite 使用 WAL；不要只复制正在写入的数据库主文件。
2. 使用配套的新面板启动原数据目录。数据库会增补字段和表，保留已有机器与历史。
   旧采样没有内存/磁盘总量、网络速率等新增字段时，图表显示缺失值，不补造历史数据。
3. 更新每台 Agent，继续使用原配置路径与 UUID。尚未绑定过单机凭证的旧身份，会生成并保存
   token，再以注册密钥完成首次绑定；保留 UUID 可以接续原机器记录。安装脚本会保留 UUID/token，
   显式传入需要使用的 `--server`、`--secret` 和 `--allow-terminal`。
4. 确认机器指标持续更新，再检查历史图表、监控执行与一条本地或指定测试渠道的通知。
   升级会有离线窗口，结合实际维护安排检查离线告警。

安装脚本强制校验 SHA256，将程序暂存在安装目录，配置成功后才替换正式二进制；配置失败时
保留原有程序，不重启服务。暂存程序不从 `/tmp` 执行，适用于 `/tmp` 挂载为 `noexec` 的机器。
这不等于整个升级可以自动回滚：若需要回退旧协议版本，应停服务并恢复配套的旧二进制与升级前
数据/配置备份，不能只替换面板程序就宣称回滚完成。

## 单机身份与注册密钥

- Agent 在连接前生成 32 字节随机 token 并保存配置，面板只存 SHA-256 哈希。
  UUID 和 token 应一起备份，不要复制到另一台机器。手动启动时显式设置 `--config`；
  不持久化配置会在重启后丢失身份。
- 已绑定身份使用 token 认证。轮换面板 `agent_secret` 不影响已绑定 Agent；尚未绑定的 Agent
  需要新注册密钥。轮换时停面板、备份并更新配置，再重启。
- 若已绑定 UUID 的 token 丢失，优先恢复该机器的配置备份。重新生成 token 或填写注册密钥
  都不能覆盖已有绑定，也无法从服务端哈希恢复原 token。
- 没有备份时，需要以新的 UUID/token 注册为新机器，历史不会自动合并。先保留原记录供查询；
  **删除机器会删除其指标历史、关联监控及规则，并永久吊销旧身份**。旧 UUID/token 无法靠注册密钥
  自动恢复。已有告警事件保留到清理期限，失去关联的规则字段为空。

卸载脚本保留 `/etc/dingzi/agent.yaml`，重装可续用。清理这份文件前应确认是否还需要原机器身份。

## 管理员密码恢复

1. 停止面板，备份 `<data>/config.yaml`。
2. 只将 `password_hash` 改成空字符串：`password_hash: ""`，保留 `agent_secret`。
3. 重启面板，从启动横幅取得新随机密码。新哈希自动保存，明文只打印这一次。

恢复不会变更注册密钥或数据库中的单机凭证。面板重启会使旧管理员 session 失效。
非空但格式无效的密码哈希、损坏的 YAML 或缺失的注册密钥会阻止启动，并保留原文件；
不要通过删除整个数据目录来恢复密码。

## HTTPS 与反向代理

Agent 依据 URL 选择加密：`https://` / `wss://` 使用 TLS，裸域名默认 HTTPS；
`http://` / `ws://` 不会自动升级。面板通过 HTTPS 对外提供服务时，启用 `--secure-cookie`。

面板和 Agent 共用一个端口，nginx 仍需正常转发 WebSocket。示例片段如下，TLS 证书按部署配置：

```nginx
# 放在 http 块内。
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

# 放在面板域名的 server 块内。
location / {
    proxy_pass http://127.0.0.1:8008;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 90s;
    proxy_send_timeout 90s;
}
```

保留外部 Host（包括非默认端口），以便浏览器 WebSocket 的来源校验。当前 UI 使用根路径的
`/api/v1/...`，请部署在独立域名的根路径；仅把页面挂在 `/dingzi/` 下不构成完整的子路径支持。

## 监控、告警与数据保留

- 每条服务监控指定一台探针。离线、任务不可执行或缺少 ICMP 权限时记“未知”，不计入可用率
  的分母。HTTP 检查接受 2xx/3xx；读取响应失败不能因已经收到 200 响应头就算正常。
- 告警每 5 秒评估。条件持续满足后触发，正常后记录恢复；未知数据不当作恢复。
  “等待触发”指尚未达到持续时间，“待发送”指已生成事件但通知尚未送出。
- 自动通知初次失败后，按 30 秒、60 秒间隔重试，总计最多 3 次；失败信息见事件记录。
  手动测试通知单独记录结果。
- 看板每 2 秒刷新；监控、规则、渠道、事件页使用刷新按钮；历史打开或切换范围时查询。
  连接中断时保留最后一次真实看板数据并提示，不显示演示机器。
- 原始指标、监控结果和告警事件默认保留 30 天，通过 `--retention-days` 调整（1–365 天），
  每小时清理一次。历史查询时聚合，没有后台持久降采样或长期归档层。
- 月度配额按 UTC 归零；不足 31 天的月份会把归零日夹到月末。
  `sum` 为入站加出站，`out` 仅出站，`max` 为两者较大值。修改归零日会清空本周期累计量。
